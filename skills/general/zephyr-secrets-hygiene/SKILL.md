# zephyr-secrets-hygiene：管的不是密钥，是「谁能读到」

> **心法：密钥治理只有两个问题 —— 谁能读到它（第一、二节），以及它坏了怎么办（第三、四节）。**
> 其余都是这两个问题的推论。

> 🔴 **「密钥绝不进代码」「破坏性变更必须有回滚路径」在 HABITS 红线节，「把正确的路修得比歪路好走」在 HABITS 元行为层 —— 那里是权威副本。** 本 skill 讲它们在密钥场景怎么落地。命令示例为 macOS，`security` / `stat -f` / `UseKeychain` 在 Linux 换等价物，分层模型与纪律不变。

**四个模式**：审计（"我的密钥有点乱"）走第一节 · 归位走第二节 · 退役（"这个还能删吗"）走第三节 · 新增与新机初始化走第四节。第四个最容易被忽略但复用率最高 —— **换电脑是这套东西真正被检验的时刻**。

## 一、审计：先扫，不碰

### 🔴 铁律：审计输出绝不含密钥值

只输出**位置 / 键名 / 权限 / 时间 / 归属**。一旦 print 值，它就进了终端历史、进了日志、进了 agent 上下文 —— 为了检查安全而制造不安全。

**这条在你身上没有代码兜底，只能靠每条命令的写法自己保证。** 扫的时候一律用「只吐键名 / 只吐文件名 / 只吐计数」的形式：

```bash
# ✅ 只取键名，值永不出现
grep -oE '^[[:space:]]*(export[[:space:]]+)?[A-Za-z_][A-Za-z0-9_]*[[:space:]]*=' <file> | tr -d ' ='

# ✅ 只报命中的文件与行号，不带内容
grep -rln 'TOKEN' <dir>

# ❌ 这些会把值吐进上下文
cat <file>          grep 'TOKEN' <file>          env | grep TOKEN
```

> 🔴 用 `grep -r` 找密钥时**默认带上 `-l` 或 `-o`**。裸 `grep -rn 'TOKEN' ~` 会把匹配行整行打出来 —— 那一行通常就包含值本身。

**扫完给用户一张表，不是一堆原始输出。** 列：位置 / 键名 / 权限 / 有没有越界（git / 云盘 / history / 全局环境）。

### 扫哪些位置

| 位置 | 找什么 |
|---|---|
| 凭据家目录（默认 `~/.secrets`） | 全部 |
| 🔴 **shell 启动文件** `.zshrc` `.zshenv` `.zprofile` `.bashrc` | `export .*（KEY\|TOKEN\|SECRET\|PASS\|CRED）` —— 最易漏，危害最大 |
| 系统标准位 | `.netrc` `.npmrc` `.pypirc` `.docker/config.json` `.aws/` `.ssh/` `.gnupg/` `.config/gh/hosts.yml` `.gradle/gradle.properties` `.pgpass` `.my.cnf` |
| OS keychain | 条目服务名（只数不取值） |
| agent / CLI 配置 | `~/.codex/auth.json`、各 agent 的 config —— 常被忘 |
| 项目内 `.env` | 排除 `*.example` / `*.template` |
| 🔴 **下载 / 桌面 / 文档目录** | `*.pem *.p8 *.p12 *.env *.keystore id_rsa*` —— 陈年遗留爱藏这儿 |
| shell history | 有没有把明文密钥打进过命令行 |
| 🔴 **云盘同步路径** | 上面任何一处是否落在 iCloud / Dropbox 内 —— 落进去约等于已发布 |

### 三个必查的病（按严重度）

1. **值不一致 ≫ 副本多。** 三个同名 token 值都不同，问题不是"多了两个"，是**没人知道哪个是活的** —— 既不敢删也不敢用。副本多只是麻烦，值不一致是已经失控。
2. **全局 export。** 文件 600 但 `export` 出去，等于所有防线都在、有人从旁边开了个洞。判据：`env | grep -iE 'TOKEN|KEY|SECRET'` 打得出东西就是病。
3. **越过边界**：进 git（`git ls-files` / `check-ignore` 逐个查）、进云盘、进 history、进 argv。

## 二、归位：按暴露面分层

**首要维度是「这一刻有多少东西能读到它」**，不是"这是 GitHub 的还是数据库的"。

| 层 | 谁能读到 | 该放什么 |
|---|---|---|
| **0 · 根本不存** | 没有长期密钥可偷 | 一切能换成 SSO / OAuth / 短期会话的。例：只存 profile 名，真凭据在 1 小时的 SSO 会话里 |
| **1 · OS keychain** | OS 加密 + 需用户授权 | 工具原生支持的（gh、ssh 口令、agent 登录态） |
| **2 · 600 文件 + 按需加载** | **只有主动加载的那个进程** | 自建 CLI 要用的 → `withkey <名> <命令>` |
| **3 · 系统标准位** | 同第 2 层，但路径由工具定死 | 搬走就断的（`.netrc`、`gradle.properties`） |
| 🔴 全局 export | **每一个子进程** | 什么都不该放 |
| 🔴 argv / git / 日志 / history | 全世界 | — |

**第 0 层优先，很多人想不到。** 能不持有密钥就不持有 —— 没有东西可偷，胜过任何"藏得好"。

**第 3 层的判据只有一条**：工具把路径硬编码了，搬走就断。满足才留，不满足一律收回第 2 层。

### 真边界不在本地

`chmod 600` 防不住 root、防不住恶意进程、防不住电脑丢了。**真边界是这把密钥在服务端能干什么。** 所以密钥治理的上游是申请权限时就要小：PAT 只勾必需 scope、DB 账号只 `GRANT SELECT`、云账号只给 ReadOnly。一把只能读的密钥泄露损失有限，一把全权限的藏得再好也是定时炸弹。

## 三、退役：删之前

**这一节出错的代价最高 —— 删错一把生产密钥，比多留十个废 token 严重得多。**

### 🔴 查真正的调用方，不是查配置文件

配置文件只告诉你"**声明了什么**"，不告诉你"**谁在用**"。

> 实测教训：一把 ssh 私钥在 `~/.ssh/config` 里只挂着两台旧机器，看起来可以退役 —— 它真正的使用者是某个项目的部署配置，路径写在那个项目的 toml 里。只查 ssh 配置会判成"没人用"，删下去直接断掉线上部署。

所以：全盘 grep 密钥的**文件名与变量名**，范围覆盖项目目录、agent 配置、CLI 脚本，不只是它"应该"待的地方。

### 🔴 否定判断前，先确认命令真的跑成功了

> 实测教训：一条 grep 的 `sed` 报了语法错、输出被吞，据此判定某文件"无人引用" —— 实际它被两处配置引用着。

**肯定判断错了会被现实打脸，否定判断错了会让你删掉不该删的东西。** 说"没有""不存在""没人用"之前，先看退出码、先确认覆盖面。

### 不 rm，进隔离区

一律 `mv` 到 `<凭据家目录>/_retired-<日期>/`（目录 `chmod 700`，内含文件 `chmod 600` —— 里面躺的是明文备份）。判错能回滚，成本几乎为零。确认无误后再整个删掉。

## 四、新增 / 新机初始化

**先定一个凭据家目录**（`chmod 700`），全部凭据只住这一处。放哪由用户定，本文一律写作 `<家目录>`，示例用 `~/.secrets`。

1. **一份凭据一个文件，文件名 = 用途**：`figma.env`，不是 `token1.env`。
2. **格式必须是 shell 能 source 的 `KEY=value`** —— 加载器靠 `. file` 载入，写成 JSON / YAML 会在 source 时炸；值含空格要加引号。`chmod 600`。
3. **说明写在凭据文件里**（注释行）：用途、来源、签发日、怎么用、轮换要改几处。那是你会打开的地方。
4. **补登记册** `<家目录>/README.md`，一份凭据一行，至少四列：`文件 | 键名 | 谁在读 | 轮换要改几处`。判据是**能和一条命令的输出对得上**（比如列目录 + 抽键名）—— 手维护的清单会漂移，机器能对账才算数。
5. **轮换路径先写好。** 换密钥时最常出事的是"改了一处漏了一处"。躲不掉的副本，就把它变成明写的副本。

### 从现状迁过来（典型：`.zshrc` 里有 export）

```bash
mkdir -p ~/.secrets && chmod 700 ~/.secrets

# ① 每个 export 拆成一个文件 —— 用管道搬运，值不经过终端
grep -m1 '^export FOO_TOKEN=' ~/.zshrc | sed 's/^export //' > ~/.secrets/foo.env
chmod 600 ~/.secrets/foo.env

# ② 写加载器（见下一节的参考实现），落在 <家目录>/loader.sh，
#    再往 ~/.zshrc 加这一行。带 -f 保护，文件不在时不会让每次开 shell 报错
echo '[ -f "$HOME/.secrets/loader.sh" ] && . "$HOME/.secrets/loader.sh"' >> ~/.zshrc

# ③ 备份 .zshrc 进隔离区，再删掉那行 export

# ④ 验证 —— 必须先剔掉当前进程继承的旧值,否则会验成假通过(见第五节)
env -u FOO_TOKEN zsh -i -c '[ -z "$FOO_TOKEN" ] && echo "已不进全局环境"'
```

### 加载器：参考实现

**这一步不能省。** 没有可用的替代品，"不许 export"三个月后一定被加回来 —— 而且不会有人知道。目标只有一个：**让按需加载比 `export` 更省事**。

照这个意思写进用户的 `<家目录>/loader.sh` 即可（名字随他喜欢）：

```bash
SECRETS_DIR="${SECRETS_DIR:-$HOME/.secrets}"

# withkey <名> <命令...> —— 只喂给这一条命令的子进程，密钥不进当前 shell
withkey() {
  local name="${1:-}"
  [ -n "$name" ] && [ $# -gt 1 ] || { echo "用法: withkey <凭据名> <命令...>" >&2; return 2; }
  shift
  local f="$SECRETS_DIR/${name}.env"
  [ -f "$f" ] || { echo "withkey: 无此凭据 '$name'" >&2; return 1; }
  ( set -a; . "$f"; set +a; exec "$@" )     # 子 shell 里加载，用完即散
}

# 列出已登记凭据 + 键名（绝不取值）—— 用来和登记册对账
keyls() {
  # ★ 目录不在就响亮地失败。静默返回 0 = 一份假的全绿报告（见第五节）
  [ -d "$SECRETS_DIR" ] || { echo "keyls: 凭据家目录不存在: $SECRETS_DIR" >&2; return 1; }
  local f n=0
  for f in "$SECRETS_DIR"/*.env; do
    [ -f "$f" ] || continue
    n=$((n+1))
    printf '%-20s %s\n' "$(basename "$f" .env)" \
      "$(grep -oE '^[[:space:]]*(export[[:space:]]+)?[A-Za-z_][A-Za-z0-9_]*[[:space:]]*=' "$f" \
         | tr -d ' =' | sed 's/^export//' | paste -sd' ' -)"
  done
  [ "$n" -gt 0 ] || echo "(空 —— $SECRETS_DIR 下还没有 *.env)" >&2
}
```

用起来：`withkey figma curl -H "X-Figma-Token: $FIGMA_TOKEN" https://api.figma.com/v1/me`

> 🔴 **这类加载器是 shell 函数，不是可执行文件。** agent 用非交互 shell 直接调会 `command not found`（`bash -c` 与 `zsh -c` 实测都是）。要用先显式 source：
> `. ~/.secrets/loader.sh && withkey figma …`

## 五、你的检查手段本身会骗你

> **安全工具倾向于"失败时静默"（不给攻击者信息），所以它们也对你静默。** 这个领域的假阴性密度高于别处 —— 每做一个否定判断，先问：**如果我的检查手段坏了，我看得出来吗？**

| 你看到的 | 真相 | 怎么防 |
|---|---|---|
| `ssh-keygen -p` 打印 `saved with the new passphrase` | 非 TTY 下它读到空输入，按提示里的 "empty for no passphrase" **设成了空口令**。成功信息是真的，口令是空的 | 独立验：`ssh-keygen -y -P "" -f <key>` 能打开就是没加上。**口令必须在真终端里设** |
| 清掉 `export` 后子 shell 里变量还在 | `zsh -i -c` **继承父进程环境**，父本来就有 | `env -u VAR zsh -i -c …` 或 `env -i` 模拟全新登录 |
| `grep -c` 明明返回 0，脚本判定却是乱的 | 计数为 0 时**退出码是 1**，`$(grep -c … \|\| echo 0)` 会吐出两个值 | `n=$(grep -c … ; true); n=${n:-0}` |
| 某条 grep 无输出 → "没人引用" | 那行的 `sed` / 管道报错了，**输出被吞** | 否定判断前先确认退出码为 0 |
| `ssh-add --apple-use-keychain` 之后 `security` 查不到条目 | **原因未定** —— 可能是落盘时机，也可能是查询姿势不对。别硬编一个解释 | 以**行为**为准：重启后第一次 ssh 还问不问口令。查询结果不是判据 |
| 公钥 comment 是 `某账号@某机器` | 那是**密钥出生地标签**，随文件走，不代表那台机器能进来 | 只当线索：它提示别处可能还留着一份副本，而**给本机 key 加口令保护不了那份副本** |

前三条不限于密钥场景 —— 凡做否定判断都适用，配合 `zephyr-quality-discipline` 的排查三纪律看。

## 反模式

❌ 为了检查安全把密钥值 print 出来 → 它就进了历史、日志和上下文。
❌ 图省事在 `.zshrc` 里 `export` → 每个子进程都读得到，防线旁边自己开了个洞。
❌ 看着像旧的就删 → 先找真正的调用方；查配置文件不算查过。
❌ 一条命令没输出就判"没人用" → 先确认它退出码是 0。
❌ 直接 `rm` → 进隔离区，几乎零成本换回滚。
❌ 三个同名 token 值不一样，"先留着以后再说" → 那不是待办，那是已经失控。
❌ 登记册靠手维护 → 会漂移；要能一条命令对账。
❌ 只把 `export` 删掉、不给替代品 → 赶时间的时候它会被加回来，而且不会有人知道。
❌ 拿 `chmod 600` 当授权边界 → 真边界是它在服务端能干什么。
❌ 把机器的具体布局写进会进 git 的文档 → 布局归本机登记册，方法论才进仓库。

## 常见问题

| 症状 | 原因 | 解决 |
|---|---|---|
| 说不清哪个 token 是活的 | 同名多值，没有单一真源 | 逐个拿它去调一次目标 API 验活性，废的删；躲不掉的副本写进登记册 |
| 换了密码，某处还在报错 | 副本多处只改了一处 | 登记册里为每份凭据写死"轮换要改几处" |
| 新电脑重配凭据要一整天 | 没登记册，全靠回忆 | 登记册 + 加载器一起同步，跟着凭据走 |
| 写了 loader 但 `withkey` 报 `command not found` | 它是 shell 函数：要么没 source，要么在非交互 shell 里跑 | 先 `. <家目录>/loader.sh` 再调 |
| 加载器找不到凭据文件 | `SECRETS_DIR` 与实际家目录不一致 | 两边对齐；别让加载器和登记册指向不同目录 |

## 本 skill 不带脚本，这是有意的

给的是**判断方法与参考实现**，不是可执行文件。原因：

- 四个模式里真正能自动化的只有"审计"和"加载"，**归位与退役本质是判断不是执行** —— 而退役恰恰是出错代价最高的一步。包成命令会让它看起来可以自动做。
- 凭据家目录放哪、加载器叫什么、用哪个 shell，都该由用户的机器决定。**发一份带死默认值的脚本，等于替所有人做了这个决定**，还得为跨 shell 兼容长期负责。
- 审计要扫哪些位置随环境变；一份固定脚本会让人以为"跑过了 = 扫全了"。

要落地就照第四节的参考实现写进用户自己的环境，让它跟着凭据走 —— 换电脑时登记册和加载器一起同步。
