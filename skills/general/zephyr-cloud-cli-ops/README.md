# zephyr-cloud-cli-ops

> 从一次真实的「网站视频资产迁腾讯云 COS+CDN」里蒸馏出的 CLI-first 云运维分工协议——用户在控制台只做了充值、开通、发密钥三件事，agent 用一把密钥完成建桶、镜像上传、免费证书、归属验证、加速域名、CNAME、HTTPS、防盗链、预热、站点白名单联动的全链，一小时内上线并双端实测验证。

## 问题陈述

云厂商的产品能力全躲在控制台后面，而控制台是为人手设计的：向导表单、多步跳转、状态散落各页。让人点控制台配一套「对象存储 + CDN + 证书 + DNS」，又慢、又不可复述、又留不下可复核的记录；让 agent 来做，常见的失败方式也很固定——

- **分工不清**：用户不知道该给 agent 什么，agent 反过来让用户去控制台点表单，两边互相等；
- **密钥处理随意**：密钥贴进命令行、留在下载目录、写进配置副本，为了省事埋下泄露面；
- **没有验证纪律**：建了就当成了，测一次速就下结论，被边缘节点的窗口期和本机 VPN 的假数据带偏诊断。

而 AI 时代的事实是：**只要一把 API 密钥加一个官方 CLI/SDK，上述全链 agent 都能独立完成**——缺的从来不是能力，是一份把分工、定序、判据、陷阱写清楚的协议。

## 解决方案

四件套，全是判断件、没有脚本：

1. **分工判据表**——「API 做不了的才轮到人」：实名、充值、开通、发密钥四类控制台专属动作怎么引导用户做，其余一切明确划给 agent，并当场拦住用户替 agent 点表单的歪路；
2. **开工四步协议**——凭据归位（接 `zephyr-secrets-hygiene`，环境变量零副本）→ 只读验活 → 摸底关键前置事实（APPID、DNS 是否同账号托管）→ 才动手；
3. **COS+CDN 十步全链蓝图**——每步「目的 + API + 完成判据」，附 faststart / 防盗链白名单 / 不可变风格 / 证书续期台账等配套纪律；
4. **实测陷阱清单**——边缘证书铺设窗口期、`--resolve` 指定节点的错误测法、本机 VPN 隧道对测速的污染、nginx reload 撞旧 worker 等，全部来自真实翻车现场。

## 核心立论

**控制台是人的界面，API 才是 agent 的界面。** 这类活的效率不来自更快的手速或预制脚本，而来自把分工划对：人只做支付与授权这类法律 / 财务动作，agent 做全部技术动作并对每一步交出可复核的判据。方法论跨云成立，本篇以腾讯云为 worked example——换云时 API 名会变，分工协议、开工定序与陷阱直觉不变。

## 蒸馏来源

一次真实的个人网站静态资产迁移实践（第三方 CloudFront 源 → 自有腾讯云 COS+CDN，2026-08）。实例坐标（域名、桶名、证书 ID、账号）均归项目记忆，不入库；陷阱清单全部来自当次实测现场，未实测的断言在文中明确标注「未实测 / 未逐一验证」。
